# i18n — next-intl (Next.js) / react-i18next (React)

**Required when the product has more than one locale.** Single-locale product:
no i18n library, but keep strings *ready*: no string concatenation for
sentences, plurals/dates/numbers through `Intl`, user-facing copy kept in the
slice (`config/` or the component), not scattered through logic.
Commands use `npm`; use the package manager detected from the lockfile.

## Where it lives (FSD)

```
messages/                         # Next: one JSON per locale (en.json, az.json, ru.json)
src/shared/config/i18n/
  routing.ts                      # Next: locales, defaultLocale, localePrefix
  request.ts                      # Next: getRequestConfig (loads messages)
  navigation.ts                   # Next: locale-aware Link, redirect, useRouter, usePathname
  i18n.ts                         # React: i18next instance
  locales/<lng>/<ns>.json         # React: one JSON per namespace
src/shared/lib/format/            # Intl helpers (formatPrice, formatDate) when reused
```

- Messages are grouped by **slice** as top-level keys / namespaces:
  `"ProductCard": {…}`, `"checkout": {…}`, `"common": {…}`. A slice reads only
  its own keys + `common`.
- Only `shared/config/i18n` imports the i18n library setup; slices import
  hooks/functions (`useTranslations`, `getTranslations`, `useTranslation`) and
  locale-aware navigation from `@/shared/config/i18n`.

## Next.js — `next-intl` (App Router)

```bash
npm i next-intl
```

```ts
// src/shared/config/i18n/routing.ts
import { defineRouting } from 'next-intl/routing'

export const routing = defineRouting({
  locales: ['en', 'az', 'ru'],
  defaultLocale: 'en',
  localePrefix: 'as-needed', // /products (en), /az/products
})
export type Locale = (typeof routing.locales)[number]
```

```ts
// src/shared/config/i18n/request.ts
import { hasLocale } from 'next-intl'
import { getRequestConfig } from 'next-intl/server'
import { routing } from './routing'

export default getRequestConfig(async ({ requestLocale }) => {
  const requested = await requestLocale
  const locale = hasLocale(routing.locales, requested) ? requested : routing.defaultLocale
  return {
    locale,
    messages: (await import(`../../../../messages/${locale}.json`)).default,
    timeZone: 'Asia/Baku', // set explicitly → no server/client markup mismatch
  }
})
```

```ts
// src/shared/config/i18n/navigation.ts
import { createNavigation } from 'next-intl/navigation'
import { routing } from './routing'

export const { Link, redirect, usePathname, useRouter, getPathname } = createNavigation(routing)
```

```ts
// next.config.ts
import createNextIntlPlugin from 'next-intl/plugin'
const withNextIntl = createNextIntlPlugin('./src/shared/config/i18n/request.ts')
export default withNextIntl(nextConfig)
```

### Routing: `[locale]` segment + `proxy.ts`

```
app/
  [locale]/
    layout.tsx           # validates locale, provider, <html lang dir>
    page.tsx
    products/[id]/page.tsx
```

```ts
// proxy.ts — locale detection (Accept-Language + cookie) and redirects
import createMiddleware from 'next-intl/middleware'
import type { NextRequest } from 'next/server'
import { routing } from '@/shared/config/i18n/routing'

const intl = createMiddleware(routing)

export function proxy(request: NextRequest) {
  // auth checks first (redirect to locale-aware /login), then:
  return intl(request)
}

export const config = { matcher: '/((?!api|_next|_vercel|.*\\..*).*)' }
```

```tsx
// app/[locale]/layout.tsx
import { hasLocale, NextIntlClientProvider } from 'next-intl'
import { setRequestLocale } from 'next-intl/server'
import { notFound } from 'next/navigation'
import { routing } from '@/shared/config/i18n/routing'

type Props = { children: React.ReactNode; params: Promise<{ locale: string }> }

export function generateStaticParams() {
  return routing.locales.map((locale) => ({ locale }))
}

export default async function LocaleLayout({ children, params }: Props) {
  const { locale } = await params
  if (!hasLocale(routing.locales, locale)) notFound()
  setRequestLocale(locale) // enables static rendering
  return (
    <html lang={locale} dir={locale === 'ar' ? 'rtl' : 'ltr'}>
      <body>
        <NextIntlClientProvider>{children}</NextIntlClientProvider>
      </body>
    </html>
  )
}
```

Pages that should render statically also call `setRequestLocale(locale)`
after awaiting `params`.

### Server first, client only in leaves

```tsx
// widgets/product-list/ui/ProductList.tsx (server)
import { getTranslations } from 'next-intl/server'

export async function ProductList() {
  const t = await getTranslations('ProductList')
  return <h2>{t('title')}</h2>
}
```

```tsx
// features/add-to-cart/ui/AddToCartButton.tsx
'use client'
import { useTranslations } from 'next-intl'

export function AddToCartButton() {
  const t = useTranslations('AddToCart')
  return <Button>{t('cta')}</Button>
}
```

- Translate in Server Components (`getTranslations`, `getFormatter`) by default;
  `useTranslations` only in leaf client components that already need `"use client"`.
  Never add `"use client"` just to translate.
- Large message files: pass only needed namespaces to the client
  (`<NextIntlClientProvider messages={pick(messages, ['AddToCart'])}>`) when
  the client bundle grows.
- Metadata: `generateMetadata` uses `getTranslations({ locale, namespace: 'Meta' })`.
- Links/redirects via `@/shared/config/i18n` (`Link`, `redirect`), never
  `next/link` with hand-built `/${locale}/…` strings.

### Typed messages

```ts
// src/global.d.ts
import type { routing } from '@/shared/config/i18n/routing'
import type messages from '../messages/en.json'

declare module 'next-intl' {
  interface AppConfig {
    Locale: (typeof routing.locales)[number]
    Messages: typeof messages
  }
}
```

`en.json` (default locale) is the source of truth; missing keys in other
locales are a CI failure (compare key sets with a small script or
`i18n-check`-style tooling run locally).

## React + Vite — `react-i18next` with lazy namespaces

```bash
npm i i18next react-i18next i18next-resources-to-backend i18next-browser-languagedetector \
  i18next-icu intl-messageformat
```

```ts
// src/shared/config/i18n/i18n.ts
import i18n from 'i18next'
import ICU from 'i18next-icu'
import LanguageDetector from 'i18next-browser-languagedetector'
import resourcesToBackend from 'i18next-resources-to-backend'
import { initReactI18next } from 'react-i18next'

export const locales = ['en', 'az', 'ru'] as const

void i18n
  .use(ICU) // same ICU message syntax as next-intl
  .use(LanguageDetector)
  .use(resourcesToBackend((lng: string, ns: string) => import(`./locales/${lng}/${ns}.json`)))
  .use(initReactI18next)
  .init({
    fallbackLng: 'en',
    supportedLngs: locales,
    ns: ['common'],
    defaultNS: 'common',
    interpolation: { escapeValue: false }, // React escapes
    detection: { order: ['querystring', 'localStorage', 'navigator'], caches: ['localStorage'] },
  })

i18n.on('languageChanged', (lng) => {
  document.documentElement.lang = lng
  document.documentElement.dir = i18n.dir(lng)
})

export { i18n }
```

- Import `./shared/config/i18n` once in `main.tsx`; `useTranslation` suspends
  while a namespace loads — the root route already has a `<Suspense>`/pending UI.
- Load a route's namespace in its `loader` to avoid a waterfall:

```ts
// src/routes/checkout.tsx
export const Route = createFileRoute('/checkout')({
  loader: () => i18n.loadNamespaces('checkout'),
  component: CheckoutView,
})
```

```tsx
// features/checkout-form/ui/CheckoutForm.tsx
const { t } = useTranslation('checkout')
return <Button type="submit">{t('submit')}</Button>
```

Typed keys:

```ts
// src/shared/config/i18n/i18next.d.ts
import 'i18next'
import type common from './locales/en/common.json'
import type checkout from './locales/en/checkout.json'

declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'common'
    resources: { common: typeof common; checkout: typeof checkout }
  }
}
```

## Message rules (both stacks)

- **No hard-coded user-facing strings** in `views`, `widgets`, `features`
  (text, `aria-label`, `alt`, `placeholder`, `title`, toasts, zod error
  messages). `entities`/`shared/ui` receive translated text via props or
  translate with their own namespace.
- **No concatenation**: `t('greeting', { name })`, never `t('hello') + name`.
  Rich text via `t.rich('terms', { link: (c) => <Link href="/terms">{c}</Link> })`
  (next-intl) / `<Trans>` (react-i18next) — no HTML strings in messages.
- **ICU plurals and selects**:

```json
{
  "Cart": {
    "items": "{count, plural, =0 {Your cart is empty} one {# item} other {# items}}",
    "greeting": "{gender, select, female {Welcome, Ms. {name}} male {Welcome, Mr. {name}} other {Welcome, {name}}}"
  }
}
```

- Keys are semantic (`checkout.submit`), not the English text.
- Validation: zod schemas return message **keys**; the form component translates.
- Backend error codes map to message keys (`errors.<CODE>`), never show raw
  backend text.

## Formatting — always `Intl`, always locale-aware

- Next: `getFormatter()` (server) / `useFormatter()` (client):
  `format.number(price, { style: 'currency', currency: 'AZN' })`,
  `format.dateTime(date, { dateStyle: 'medium' })`, `format.relativeTime(date)`.
- React: ICU in messages (`{price, number, ::currency/AZN}`, `{date, date, medium}`)
  or `Intl.NumberFormat(i18n.language, …)` in `shared/lib/format`.
- Never `toFixed` + currency symbol, never manual date strings, never
  `toLocaleString()` without an explicit locale.
- Dates cross the server/client boundary as ISO strings; set `timeZone`
  explicitly to avoid hydration mismatches.

## RTL readiness

- Tailwind logical utilities: `ms-*`/`me-*`, `ps-*`/`pe-*`, `start-*`/`end-*`,
  `text-start`/`text-end`, `rounded-s-*` — not `ml-*`/`mr-*`/`left-*`/`text-left`.
- Directional icons (arrows, chevrons) flip with `rtl:rotate-180`.
- `dir` set on `<html>` from the active locale (shown above).

## Testing

- Unit: wrap `renderWithProviders` with `NextIntlClientProvider locale="en"
  messages={en}` or an i18next instance initialised with `en` resources
  synchronously; assert on the English text.
- CI check: every locale has the same key set as the default locale.
- E2E: one smoke spec per extra locale (`/az`) checks `lang`/`dir` and a
  translated heading.

## Rules

- >1 locale → next-intl (Next) / react-i18next + ICU (React); config only in
  `shared/config/i18n`.
- Translate on the server by default (Next); client hooks only in leaves.
- No hard-coded user-facing strings in `views`/`widgets`/`features`; no concatenation.
- ICU plurals; `Intl` for numbers/dates/currency with explicit locale.
- Locale-aware `Link`/`redirect`; logical (RTL-safe) Tailwind utilities.
- Typed messages; default-locale JSON is the source of truth.
